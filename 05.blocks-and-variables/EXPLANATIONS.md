# 05. ブロックと変数: 問題別の詳しい解説

この章の問題は、計算結果だけでなく「実行中に変数の値がどう変わるか」を読む練習です。trace 問題では、上から順に文を実行し、変数に値が入った瞬間だけ表に書き込みます。`Lib.print` の行では、変数の値は変わらず、何が印字されたかを右側に書く、と考えると迷いにくくなります。

## 5.4.E1

- 読むもの・入力: 入力はありません。コード内の変数 `a` が、どの行でどの値になるかを追います。
- 追い方: 最初に `let a;` のように宣言だけされると、値は `undefined` です。そのあと `a = 0;`、`a = 1;`、`a = 2;`、`a = 3;` のように代入されるたびに、表の `a` の欄を新しい値で更新します。
- 印字の考え方: `Lib.print(a);` が実行された時点の `a` の値を印字します。以前の値ではなく、その行に来た瞬間の最新の値です。
- 出力の形: この問題では `undefined`、`0`、`1`、`2`、`3` のように、代入前と代入後の値が順に印字されます。
- よくあるミス: `let a;` を「0が入った」と考えてしまうことです。値を入れていない変数は `undefined` で、0とは別の値です。

## 5.4.E2

- 読むもの・入力: 入力はありません。`a` に奇数が順に入っていくコードを追います。
- 追い方: `a` に最初の値が入り、そのあと `a = a + 2;` のような文が実行されるたびに、今の `a` に2を足して新しい `a` にします。
- 代入文の読み方: `a = a + 2;` は数学の等式ではありません。「右側の `a + 2` を今の値で計算し、その結果を左側の `a` に入れ直す」という意味です。
- 出力の形: `1`、`3`、`5`、`7` のように、更新された `a` が順に印字されます。
- よくあるミス: `a = a + 2` を「常に成り立つ式」と考えることです。プログラムでは、右を計算して左へ入れる命令です。

## 5.4.E3

- 読むもの・入力: 入力はありません。`a` と `sum` の2つの変数を追います。
- 追い方: `a` は次に足す数、`sum` はここまでの合計です。`sum = sum + a;` が出てきたら、今の `sum` に今の `a` を足して、結果をまた `sum` に入れます。
- 変数の役割: `a` は `0, 1, 2, 3, 4` のように変わり、`sum` は `0, 1, 3, 6, 10` のように育ちます。`a` と `sum` を混ぜずに、表の別々の列で追うのが大切です。
- 出力の形: `sum` の値が更新されるたびに印字されるので、合計の途中経過が1行ずつ表示されます。
- よくあるミス: `sum` を毎回0に戻してしまうことです。累積する変数は、前回までの値を残して、そこに新しい値を足します。

## trace 問題を解く手順

1. まず変数名の列を確認します。`a` だけなのか、`a` と `sum` のように複数あるのかを見ます。
2. コードを上から1行ずつ読みます。飛ばして先の行を見ないようにします。
3. `let` で変数が作られたら、その変数が使える範囲を確認します。
4. `=` の文があれば、右側を先に計算して、その結果を左側の変数に入れます。
5. `Lib.print(...)` の文があれば、その時点の値が印字されます。変数の値そのものは変わりません。
6. 表の `***` は「その時点で確定する値」だけを入れます。想像で未来の値を書かないようにします。

## この章で特に大事なこと

- `let a;` は変数を作るだけです。まだ意味のある数値は入っていません。
- `let a = 1;` は変数を作ると同時に値を入れます。
- `a = 3;` は、すでにある変数 `a` の中身を新しい値に更新します。
- `a = a + 1;` は、今の `a` に1を足して、その結果で `a` を上書きします。
- ブロック `{ ... }` の中で作った変数は、そのブロックの外から使えないことがあります。
