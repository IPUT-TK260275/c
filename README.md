# プログラミング練習用リポジトリ

このリポジトリは、授業や自習で JavaScript の基礎を練習するためのものです。

プログラミング経験が 0 の人でも、上から順番に進めれば「ファイルを開く」「プログラムを実行する」「入力を渡す」「採点する」「提出する」までできるように書いています。分からない言葉が出てきたら、まずこの README の「よく使う言葉」と「困ったとき」を見てください。

## 最初に知っておくこと

この教材では、主に次の 3 つを使います。

| 使うもの | 何をするものか |
| --- | --- |
| VS Code | プログラムを書くためのエディタ |
| ターミナル | 文字で命令を入力して、プログラムを実行する場所 |
| Node.js | JavaScript のプログラムを動かすための実行環境 |

プログラムを書くファイルの多くは `.js` で終わります。たとえば `03.first-step/3.4.E1.js` は JavaScript のファイルです。

## このリポジトリの開き方

1. VS Code を開きます。
2. `File` → `Open Folder...` を選びます。
3. このフォルダを選びます。
4. VS Code のメニューから `Terminal` → `New Terminal` を選びます。

この教材は、WSL/Ubuntu のターミナルで動かす前提です。Windows の PowerShell やコマンドプロンプトで `node` を実行すると、教材用の `lib.js` が見つからないことがあります。

VS Code のターミナル名が `bash`、`Ubuntu`、`WSL` のようになっていれば大丈夫です。`PowerShell` と表示されている場合は、ターミナル右上のメニューから WSL/Ubuntu 側のターミナルを開いてください。

ターミナルを開いたら、次のコマンドで今いる場所を確認できます。

```bash
pwd
```

この教材のフォルダにいるときは、`README.md` や `03.first-step` などが見えます。

```bash
ls
```

もし `README.md` が見えなければ、別の場所にいます。VS Code でこのフォルダを開き直してください。

## 最初の動作確認

まず Node.js が使えるか確認します。

```bash
node --version
```

`v20...` や `v22...` のようなバージョンが表示されれば OK です。

`node: command not found` と出る場合は、WSL/Ubuntu に Node.js が入っていません。Ubuntu のターミナルで次を実行してから、もう一度 `node --version` を確認してください。

```bash
sudo apt update
sudo apt install -y nodejs npm
```

次に、この教材の補助ファイル `lib.js` が見えるか確認します。

```bash
ls ~/c/lib.js
```

`/home/ユーザー名/c/lib.js` にある前提でプログラムが作られています。別の場所に置いている場合は、`~/c` にこのリポジトリを置くのが一番簡単です。

## プログラムの基本形

この教材の JavaScript ファイルは、だいたい次の形で書きます。

```js
"use strict";
const Lib = require(require("os").homedir() + "/c/lib.js");
{
    // ここに処理を書く
}
```

`Lib` は、この教材で入力と出力を簡単に使うための道具です。

| 書き方 | 意味 |
| --- | --- |
| `Lib.print(x)` | `x` を画面に出力する |
| `Lib.input()` | 入力を 1 行読む |
| `Number(x)` | 文字列を数値に変える |
| `let name = x;` | `x` に `name` という名前を付ける |

たとえば、2 行の入力を数値として読み、かけ算して出力するならこう書きます。

```js
"use strict";
const Lib = require(require("os").homedir() + "/c/lib.js");
{
    let price = Number(Lib.input());
    let count = Number(Lib.input());

    Lib.print(price * count);
    Lib.print("\n");
}
```

最後の `Lib.print("\n");` は改行です。出力例と完全に同じにするため、最後の改行も大事です。

## プログラムを実行する

ターミナルで `node ファイル名` と入力します。

```bash
node 03.first-step/3.4.E1.js
```

入力が必要なプログラムは、実行後にターミナルへ値を打ちます。入力例が次のように 2 行なら、

```text
100
3
```

実行中に `100` と入力して Enter、次に `3` と入力して Enter を押します。

毎回手で入力する代わりに、次のように一度に渡すこともできます。

```bash
printf '100\n3\n' | node 03.first-step/3.4.E1.js
```

`100\n3\n` は「100、改行、3、改行」という意味です。

## 文法エラーを確認する

プログラムが実行できないときは、まず文法チェックをします。

```bash
node --check 06.selection/6.5.E1.js
```

何も表示されなければ、少なくとも文法エラーはありません。

エラーが出た場合は、最初に表示された `ファイル名:行番号` を見ます。たとえば `6.5.E1.js:12` と出たら、`6.5.E1.js` の 12 行目付近を確認します。

## 採点する

採点には `grademe.sh` を使います。

特定のファイルだけ採点する例です。

```bash
./grademe.sh 06.selection/6.5.E1.js
```

全体を確認する例です。

```bash
./grademe.sh --check-all
```

採点で 100 点にならないときは、次の順番で確認してください。

1. 実行時エラーが出ていないか。
2. 出力の文字、空白、改行が問題文の例と同じか。
3. 入力を読む回数が足りているか、多すぎないか。
4. 数値入力に `Number(Lib.input())` を使っているか。
5. 条件分岐や繰り返しが、境界値でも正しく動くか。

## 提出する

提出には `submit.sh` を使います。

1 ファイルだけ提出する例です。

```bash
./submit.sh 06.selection/6.5.E1.js
```

まとめて提出する例です。

```bash
./submit.sh --all
```

`submit.sh` は、先にローカル採点を実行し、100 点のものだけ提出します。うまく提出できない場合は、ネットワーク、ログイン状態、または `.tls` の設定が原因のことがあります。

Windows で配布された採点・提出スクリプトを更新したいときは、次を実行します。

```bat
update.bat
```

## よくあるミス

| ミス | 直し方 |
| --- | --- |
| 数値入力をそのまま計算してしまう | `Number(Lib.input())` を使う |
| 最後の改行がない | 最後に `Lib.print("\n");` を書く |
| 空白が多い、または少ない | 出力例と同じ場所だけ `" "` を出す |
| 比較のつもりで `=` を使う | 比較は `===`、代入は `=` |
| `a < b < c` と書く | `a < b && b < c` と書く |
| `while` が終わらない | ループ内でカウンタを更新しているか確認する |
| 入力を読みすぎる | 問題文の入力例が何行あるか数える |
| ファイルが見つからない | `ls` で今いる場所を確認する |

## エラーの読み方

エラーは怖く見えますが、最初に見る場所は決まっています。

### `SyntaxError`

文法エラーです。かっこ、引用符、セミコロン、`if` や `while` の形を確認します。

```text
SyntaxError: Unexpected token
```

「予想していない記号がある」という意味です。表示された行番号の前後を見てください。

### `ReferenceError`

名前の間違いです。

```text
ReferenceError: total is not defined
```

`total` という名前がまだ作られていない、またはスペルが違うという意味です。

### `Cannot find module`

必要なファイルが見つからないという意味です。

```text
Error: Cannot find module
```

この教材では、次のどちらかで起きやすいです。

1. Windows の PowerShell で実行している。
2. リポジトリを `~/c` 以外の場所に置いている。

ターミナルで `pwd` と `ls ~/c/lib.js` を実行して、WSL/Ubuntu 側で `~/c` の中にいるか確認してください。

## 問題を解くときの手順

いきなり全部を書こうとせず、次の順番で進めると失敗しにくいです。

1. 問題文の入力例を見て、入力が何行あるか数える。
2. 数値なら `Number(Lib.input())`、文字列なら `Lib.input()` で読む。
3. 出力例に `---` があれば、先に `Lib.print("---\n");` を書く。
4. 必要な計算や条件分岐を書く。
5. `Lib.print(...)` で答えを出す。
6. 最後に `Lib.print("\n");` を書く。
7. `node --check` で文法を確認する。
8. 入力例を `printf` で渡して、出力例と見比べる。
9. `grademe.sh` で採点する。

## 入力と出力の例

問題文に次の入力例があるとします。

```text
100
3
```

そして出力例が次だとします。

```text
---
300
```

この場合のプログラム例です。

```js
"use strict";
const Lib = require(require("os").homedir() + "/c/lib.js");
{
    let price = Number(Lib.input());
    let count = Number(Lib.input());

    Lib.print("---\n");
    Lib.print(price * count);
    Lib.print("\n");
}
```

実行例です。

```bash
printf '100\n3\n' | node 03.first-step/3.4.E1.js
```

## よく使う言葉

| 言葉 | 意味 |
| --- | --- |
| コマンド | ターミナルに入力する命令 |
| ディレクトリ | フォルダのこと |
| カレントディレクトリ | 今ターミナルがいる場所 |
| 入力 | プログラムに渡される値 |
| 出力 | プログラムが画面に表示する値 |
| 文字列 | `"hello"` のような文字のまとまり |
| 数値 | `123` や `3.14` のような計算できる値 |
| 変数 | 値に名前を付けたもの |
| 条件分岐 | 条件によって処理を変えること |
| 繰り返し | 同じ処理を何度も実行すること |
| 配列 | 複数の値を順番に並べたもの |

## 困ったとき

まず、次の 4 つを確認してください。

```bash
pwd
ls
node --version
ls ~/c/lib.js
node --check 直したいファイル名.js
```

それでも分からないときは、質問するときに次の情報を一緒に出すと、原因を見つけやすくなります。

1. どのファイルを直しているか。
2. 実行したコマンド。
3. 入力した値。
4. 期待した出力。
5. 実際に出た出力またはエラー全文。

例です。

```text
ファイル: 06.selection/6.5.E1.js
コマンド: printf '10\n20\n' | node 06.selection/6.5.E1.js
期待した出力:
20

実際の出力:
10
```

「動きません」だけだと原因を特定しにくいですが、上の 5 点があるとかなり調べやすくなります。
