# 06. 条件分岐 問題別の詳しい解説

6章は、条件に応じて出力や計算を変える章です。問題文に「なら」「そうでなければ」「以上」「未満」などが出てきたら、それを `if` の条件に直します。

## 条件分岐の基本

```js
if (条件) {
    // 条件が true のとき
} else {
    // 条件が false のとき
}
```

比較には `===`, `!==`, `<`, `<=`, `>`, `>=` を使います。`=` は代入なので、条件判定には使いません。

## 6.5.R1.1 / 6.5.R1.2

- 目的: 入力された整数が奇数か偶数かを判定するコードの trace を作ります。
- 見る条件: `a % 2 > 0` です。`a % 2` は2で割った余りなので、奇数なら1、偶数なら0になります。
- traceの書き方: 条件が `true` なら `if` 側の `Odd`、`false` なら `else` 側の `Even` だけを書きます。
- 注意: `if` と `else` の両方は実行されません。どちらか一方だけです。

## 6.5.R2.1 / 6.5.R2.2

- 目的: 入れ子の `if` を含む診断コードの trace を作ります。
- 手順: まず最初の入力 `a` が `"Gold"` かどうかを見ます。そこで外側の分岐が決まります。
- 次の入力: 外側で選ばれたブロックの中で、もう1つ入力 `b` を読み、その値で内側の分岐を決めます。
- 注意: 外側で通らなかった側の `Lib.input()` は実行されません。入力を読む場所も分岐に影響されます。

## 6.5.R3

- 目的: 入力されたたい焼きの種類に応じて価格を出すコードの trace を作ります。
- 見る条件: `a === "Tsubuan"`, `a === "Koshian"`, `a === "Castard"` を上から順に見ます。
- 手順: 最初に当てはまったところだけ実行されます。どれにも当てはまらなければ `else` です。
- 注意: `else if` は上から順番です。後ろの条件は、前の条件が外れたときだけ調べます。

## 6.5.E1

- 入力: 整数 `a` を読みます。
- 条件: `a < 0` なら負の数です。
- 出力: 負なら `NEGATIVE`、そうでなければ `NONNEGATIVE` です。
- 注意: `0` は負ではありません。`NONNEGATIVE` 側です。

## 6.5.E2

- 入力: 整数 `a`, `b` を読みます。
- 条件: `a === b` なら等しいです。
- 出力: 等しければ `EQUAL`、そうでなければ `UNEQUAL` です。
- 注意: 比較は `===` です。`=` ではありません。

## 6.5.E3

- 入力: 単価 `price` と個数 `number` を読みます。
- 条件: 合計 `price * number` が5000以下なら買えます。
- 出力: 買えるなら `CAN`、買えないなら `CANNOT` です。
- 注意: 「以下」は `<=` です。5000ちょうどは買える側です。

## 6.5.E4

- 入力: 単価と個数を読みます。
- 計算: まず `total = price * number` を作ります。合計が2000以上なら送料230円、そうでなければ460円を足します。
- 出力: 送料込みの合計を出します。
- 注意: 送料を足した後の値を出すので、`total` を更新すると分かりやすいです。

## 6.5.E5

- 入力: 年 `year` を読みます。
- 条件: うるう年なら366日、そうでなければ365日です。
- 判定順: `400` で割り切れるなら366、次に `100` で割り切れるなら365、次に `4` で割り切れるなら366です。
- 注意: 順番が大事です。`4` の判定を最初にすると、100で割り切れる年を間違えます。

## 6.5.E6

- 入力: `a`, `b` を読みます。
- 目的: 小さい順に2つの数を出します。
- 条件: `a <= b` なら `a b`、そうでなければ `b a` と出します。
- 注意: 同じ値の場合はどちらの順でも同じですが、`a <= b` 側にしておくと自然です。

## 6.5.E7

- 入力: `a`, `b`, `c` を読みます。
- 目的: 3つの数を小さい順に出します。
- 考え方: まず `a <= b` かで大きく分け、その中で `c` がどこに入るかを調べます。
- 注意: 3つの並び方は6通りあります。条件を漏らさないよう、出力例を自分で作って試すと安全です。

## 6.5.E8

- 入力: 日付 `d` を読みます。
- 考え方: 曜日は7日ごとに繰り返します。`d % 7` の値ごとに曜日を出します。
- 出力: 余りが1なら Friday、2なら Saturday、という対応を `else if` で書きます。
- 注意: 余り0の場合もあります。最後の `else` で Thursday を出します。

## 6.5.E9

- 入力: 整数 `a` を読みます。
- 条件: `a < 0` なら `NEGATIVE`、`a === 0` なら `ZERO`、それ以外は `POSITIVE` です。
- 注意: 0を正の数に入れないようにします。負、ゼロ、正の3分岐です。

## 6.5.E10

- 入力: 2つの文字列 `a`, `b` を読みます。
- 考え方: それぞれが `"N"` かどうかで、4通りに分かれます。
- 出力: 両方 `N` なら `Newdays`、片方だけ `N` なら `Saizeriya`、両方違うなら `Disney` です。
- 注意: 文字列の比較なので `a === "N"` と書きます。

## 6.5.E11

- 入力: 略称文字列 `a` を読みます。
- 条件: `USJ`, `TDL`, `TDS`, `TDM` を上から順に比べます。
- 出力: 対応する正式名称を出し、どれでもなければ `UNKNOWN` です。
- 注意: `else if` を使うと、1つ見つかった時点で残りを調べずに済みます。

## 6.5.E12

- 入力: `year`, `month` を読みます。
- 考え方: 2月だけうるう年の判定が必要です。4, 6, 9, 11月は30日、それ以外は31日です。
- 手順: 先に `month === 2` を調べ、2月ならE5と同じうるう年判定を使います。
- 注意: 月ごとに日数が違います。2月を特別扱いするのがポイントです。

## 6.5.E13

- 入力: 4つの整数 `a`, `b`, `c`, `d` を読みます。
- 考え方: `min = a` と仮に決め、`b`, `c`, `d` がそれより小さければ `min` を更新します。
- 出力: 最後に残った `min` が最小値です。
- 注意: `if` は3つとも独立に書きます。`else if` にすると、後ろの値を調べ損ねる場合があります。

## 6.5.E14

- 入力: `a`, `b` を読みます。
- 計算: 点数は `3 * a + b` です。
- 条件: 点数が20を超えたら `OUT`。そうでなければ、残り `20 - point` を出します。
- 注意: `20` ちょうどはまだ `OUT` ではありません。`point > 20` です。
