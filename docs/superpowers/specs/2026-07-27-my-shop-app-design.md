# MY SHOP APP 総合演習 設計

## 目的

総合演習 13.1〜13.3 の未完成テンプレートを、教材で既に扱われている基本的な JavaScript の構文と `lib.js` の関数を中心に完成させる。

## 成果物

`13.integrated-dev/` に次の3ファイルを作成する。

- `my-shop-app.1.js`: 処理をコマンド分岐内へ直接記述する CUI 版
- `my-shop-app.2.js`: 同じ CUI の処理を関数で整理した版
- `my-shop-app.web.js`: HTTP サーバーを利用する Web 版

教材のテンプレートで「以下は変更する必要はありません」と示された範囲は変更せず、「問」の範囲を中心に実装する。

## 商品データ

商品は次のプロパティを持つ連想配列として扱う。

- `id`: 自動採番される整数
- `name`: 空でない商品名
- `price`: 整数価格
- `description`: 空でない説明

初期商品と `next_id` はテンプレートの値を維持する。商品の追加時だけ `next_id` を1増やし、削除したIDは再利用しない。

## CUI版の動作

### 検索

商品名に入力キーワードが含まれる商品だけを対象にする。比較は大文字・小文字を区別する。結果は入力された `name`、`price`、`description` のいずれかの値について昇順に並べ、`show` と同じ形式で表示する。同値の商品がある場合の順序は元のリスト順を維持する。

検索表示のために元の `products` の順序は変更せず、検索結果用の配列を作る。

### ID検証

CUIから読み取ったIDは文字列なので、`String(product["id"])` と入力文字列を比較する。一致する商品がなければ `Enter a valid ID.` を表示して再入力させる。

### 更新

有効なIDを受け取った後、追加処理と同じ規則で名前、整数価格、説明を読み取る。対象商品の `name`、`price`、`description` を入力値で置き換え、IDは変更しない。

### 削除

有効なIDの商品位置を調べ、`Lib.splice` でその商品を1件削除する。

13.1 と 13.2 の画面表示、入力検証、商品操作の結果は同一にする。13.2 ではテンプレートどおり各コマンドを関数に分ける。

## Web版の動作

### ソート

`sortProducts(order)` は次の6種類を扱い、`products` 自体を並べ替える。

- `id_asc` / `id_desc`
- `name_asc` / `name_desc`
- `price_asc` / `price_desc`

未知の `order` では順序を変更しない。同値の場合は元の順序を維持する。

### 追加・更新・削除

- `addProduct` は `newProduct` で商品を作り、`products` に追加する。
- `updateProduct` は数値IDが一致する商品の名前、価格、説明を更新し、IDは維持する。
- `deleteProduct` は数値IDが一致する商品を1件削除する。
- 更新・削除でIDが見つからない場合は、商品リストを変更しない。

HTTPフォーム側の入力検証追加は課題の範囲外とし、既存の変換処理を維持する。

## テストと検証

自動テスト用に、標準入力を与えてCUIプログラムを実行し、標準出力を検査する。少なくとも次を確認する。

- 初期商品一覧の表示
- 部分一致検索と3項目の昇順
- 無効なソート項目からの再入力
- 商品の追加と自動採番
- 無効なIDからの再入力
- 更新後の商品情報
- 削除後の商品一覧
- 不正コマンドと終了

Web版は商品操作関数をテスト可能な形で評価し、6種類のソート、追加、自動採番、更新、削除、存在しないIDの非変更を検査する。最後に全ファイルへ構文検査を行う。

## 非対象

- データのファイルまたはデータベースへの永続化
- 認証、認可、CSRF対策などの本番運用機能
- HTMLや画面デザインの変更
- テンプレート外の大規模な共通化やリファクタリング
